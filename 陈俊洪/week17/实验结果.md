# GRPO 算术题模型对比报告

## 1. 实验概览

| 项目 | 说明 |
|------|------|
| 任务 | 中文算术题求解，答案须包在 `<answer>N</answer>` 标签内 |
| 基座模型 | Qwen2.5-0.5B-Instruct（494,032,768 参数；24 层，hidden 896，GQA 14/2 头） |
| 算法 | GRPO（Group Relative Policy Optimization），TRL `GRPOTrainer` |
| 奖励 | 纯规则可验证奖励，无奖励模型、无人工标注：`reward_correct`(1.0) + `reward_format`(0.2) |
| 训练集 | 程序化生成 1000 题，难度配比 L3 50% / L5 25% / L2 25%（seed=123） |
| 训练量 | 200 优化步 × 4 prompt/步 × 8 采样 = 6400 条 completion（0.8 epoch） |
| 评估集 | 6 难度 × 50 题 = 300 题，**seed=42 三个模型完全一致**，可配对比较 |
| 解码方式 | greedy ×1（确定性能力）+ 温度 1.0 采样 ×8（pass@8 与组内多样性） |
| 硬件 | RTX 4060 Laptop 8GB（单卡） |
| 软件 | torch 2.12.1+cu126 / transformers 5.3.0 / trl 1.12.0 / peft 0.18.1 / accelerate 1.13.0 |

难度分级（`probe_baseline.py:make_problem`）：

| 级别 | 题型 | 是否进训练集 |
|------|------|:---:|
| L1_add_1digit | 个位数加法 | — |
| L2_addsub_2digit | 两位数加减 | √ (25%) |
| L3_addsub_3digit | 三位数加减 | √ (50%) |
| L4_mul_1digit | 表内乘法（一位×一位） | — |
| L5_mul_2x1digit | 两位数×一位数 | √ (25%) |
| L6_mul_2x2digit | 两位数×两位数 | — |

L1 / L4 / L6 **刻意不进训练集**，专门用来回答"没训过的难度会不会跟着提升"。

### 三个对比模型

| # | 模型 | 训练方式 | 可训练参数 | 学习率 | 训练耗时 | 峰值显存 | 落盘体积 |
|---|------|---------|-----------|-------|---------|---------|---------|
| A | **基线** | 无（Qwen2.5-0.5B-Instruct 原始权重） | — | — | — | 1.54 GB（仅推理） | — （复用基座 942 MB） |
| B | **全量 GRPO** | 全参数微调，200 步 | 494,032,768（100%） | 2e-6 | 614.8 s | 5.51 GB | 946 MB |
| C | **LoRA GRPO** | LoRA r=16 α=32，注入 q/k/v/o_proj，200 步 | 2,162,688（**0.44%**） | 2e-4 | 456.7 s | **2.31 GB** | **12 MB** |

三者共享同一套 GRPO 超参：`num_generations=8`、`beta=0.0`（不加载参考模型）、`epsilon=0.2`、
`temperature=1.0`、`max_completion_length=64`、`per_device_train_batch_size=8` × `gradient_accumulation_steps=4`。

## 2. 核心指标说明


| 指标 | 定义 | 读什么 |
|------|------|-------|
| **格式率** `greedy_format_rate` | 输出中能匹配 `<answer>\s*-?\d+\s*</answer>` 的比例 | 指令遵循（表层行为） |
| **严格准确率** `greedy_strict_acc` | 有标签**且**标签内数字正确 | 端到端可用性（格式 ∧ 算对） |
| **宽松准确率** `greedy_loose_acc` | 输出中**最后一个数字**正确（忽略格式） | 纯计算能力 |
| **采样准确率** `sample_loose_acc` | 400 条采样（50 题 × 8）里正确的比例 | 概率分布整体质量，非只看 top-1 |
| **pass@8** | 8 条采样里至少 1 条正确的题目比例 | **能力上界**：模型"知不知道"这题的答案 |
| **informative group rate** | 8 条采样里 `0 < 正确数 < 8` 的题目比例 | **GRPO 的训练燃料**：组内全对或全错时 advantage=(r−mean)=0，不产生任何梯度 |

`reward_correct` 用的是**宽松**口径。原因：如果正确分也要求标签，冷启动期格式率不足时正确信号会被格式抹平，
组内奖励全零 → advantage 全零 → 训练根本启动不了。格式由独立的 `reward_format` 单独驱动，两个信号解耦。

## 3. 贪心解码准确率对比（核心表）

> 以下为各难度级别贪心解码的**格式率 / 严格准确率 / 宽松准确率**对比。
> 每格式为 `基线 → 全量GRPO → LoRA GRPO`，n=50，seed=42（三模型同题）。

| 难度 | 训练集 | 格式率 | 严格准确率 | 宽松准确率 |
|------|:---:|---|---|---|
| L1_add_1digit | — | 0.46 → **1.00** → **1.00** | 0.46 → **1.00** → **1.00** | 0.94 → 1.00 → 1.00 |
| L2_addsub_2digit | √ | 0.46 → **1.00** → **1.00** | 0.46 → **1.00** → **1.00** | 0.82 → **1.00** → **1.00** |
| L3_addsub_3digit | √ | 0.68 → **1.00** → **1.00** | 0.60 → 0.94 → **0.96** | 0.78 → 0.94 → **0.96** |
| L4_mul_1digit | — | 0.48 → **1.00** → **1.00** | 0.48 → **1.00** → **1.00** | 0.98 → 1.00 → 1.00 |
| L5_mul_2x1digit | √ | 0.62 → **1.00** → **1.00** | 0.60 → **0.98** → **0.98** | 0.92 → 0.98 → 0.98 |
| L6_mul_2x2digit | — | 0.52 → **1.00** → **1.00** | 0.30 → **0.56** → 0.46 | 0.46 → **0.56** → 0.46 |
| **宏平均** | | **0.537 → 1.000 → 1.000** | **0.483 → 0.913 → 0.900** | **0.817 → 0.913 → 0.900** |

### 关键发现

**1. 格式遵循：0.537 → 1.000，六个难度全部满分。**
基线的行为是"随机想起来才加标签"——同一个模型对 `5 + 4` 输出 `<answer>9</answer>`，对 `2 + 1` 只输出 `3`。
训练后 300 道题**无一例外**都带标签，包括三个没进训练集的难度。格式是一个不依赖具体题目的**表层策略**，
RL 学得极快：训练日志里 `reward_format/mean` 在第 10 步就到 0.188（= 94% 的采样已带格式），第 15 步到 0.198（99%）。

**2. 严格准确率 +43 个百分点，但其中约 3/4 来自"解除格式封锁"，不是算力提升。**
这是本实验最需要点明的归因问题。基线的宽松准确率是 0.817，严格准确率只有 0.483 ——
**中间 33.4 个百分点的差距，全是"算对了但没打标签"被判为失败**。GRPO 带来的 43.0 个百分点提升可以拆成：

| 收益来源 | 幅度 | 说明 |
|---------|:---:|------|
| 格式解锁（宽松已对，补上标签） | ≈ +33.4 pt | 把 0.483 抬到 0.817 这条"本来就该拿到"的线 |
| 真实计算能力提升 | ≈ +9.7 pt | 宽松准确率 0.817 → 0.913，这部分才是模型真的算得更准了 |

如果只报"准确率从 0.48 涨到 0.91，接近翻倍"，就是把指令遵循的收益冒充成了推理能力的收益。

**3. 真实计算能力确实有提升，且集中在中等难度。**
宽松准确率的增量分布很不均匀：L2 +0.18、L3 +0.16、L6 +0.10，而 L1/L4/L5 因为基线已经 0.92~0.98，
基本没有空间（天花板效应）。这个分布和训练集配比（L3 50% / L2 25% / L5 25%）以及基线的
informative group rate（L3 0.78、L5 0.68、L2 0.66 最高）高度吻合——**GRPO 只在"有梯度可拿"的地方长本事**。

**4. L6（两位数×两位数）是能力边界，格式给满但算力几乎不动。**
L6 格式率同样冲到 1.00（说明表层行为泛化毫无阻碍），但全量的宽松准确率只从 0.46 爬到 0.56，
LoRA 更是停在 0.46（一分算力没长，它的严格准确率 0.30 → 0.46 全部来自格式）。
更硬的证据在 §4.2：L6 的 loose pass@8 **完全没动**（0.72 → 0.72 → 0.68）。多步进位乘法超出 0.5B 模型的
能力边界，给多少奖励都学不会。

## 4. 采样准确率与 pass@8 对比

### 4.1 采样平均准确率

温度 1.0 采样，每难度 50 题 × 8 条 = 400 条 completion 的平均正确率（`基线 → 全量 → LoRA`）：

| 难度 | 严格采样准确率 | 宽松采样准确率 |
|------|---|---|
| L1_add_1digit | 0.480 → 0.990 → 0.990 | 0.870 → **1.000** → 0.990 |
| L2_addsub_2digit | 0.380 → 0.990 → **1.000** | 0.760 → 1.000 → **1.000** |
| L3_addsub_3digit | 0.410 → 0.930 → **0.950** | 0.670 → 0.930 → **0.960** |
| L4_mul_1digit | 0.530 → 0.990 → **1.000** | 0.890 → 0.990 → **1.000** |
| L5_mul_2x1digit | 0.470 → 0.950 → **0.960** | 0.800 → 0.960 → **0.970** |
| L6_mul_2x2digit | 0.240 → **0.520** → 0.470 | 0.380 → **0.520** → 0.480 |
| **宏平均** | **0.419 → 0.897 → 0.897** | **0.727 → 0.900 → 0.900** |

宽松采样准确率 0.727 → 0.900（+17.3 pt），提升幅度是 greedy 宽松准确率（+9.7 pt）的近两倍。
这不是巧合：采样准确率衡量的是**整条概率分布**的质量，而 GRPO 干的正是把概率质量从错误答案挪到正确答案上。
基线在温度 1.0 下会"偶尔手滑"（greedy 0.817 但采样只有 0.727，掉 9 个点），训练后这个缺口收窄到 1.3 个点
（0.913 vs 0.900）——策略变得几乎确定性，采样和 greedy 趋于一致。这一点在 §6.3 的熵曲线上有直接对应。

### 4.2 pass@8

| 难度 | 严格 pass@8 | 宽松 pass@8 |
|------|---|---|
| L1_add_1digit | 0.98 → 1.00 → 1.00 | 1.00 → 1.00 → 1.00 |
| L2_addsub_2digit | 0.96 → 1.00 → 1.00 | 0.98 → 1.00 → 1.00 |
| L3_addsub_3digit | 0.92 → 0.96 → **0.98** | 0.96 → 0.96 → **0.98** |
| L4_mul_1digit | 1.00 → 1.00 → 1.00 | 1.00 → 1.00 → 1.00 |
| L5_mul_2x1digit | 0.96 → 1.00 → 1.00 | 1.00 → 1.00 → 1.00 |
| L6_mul_2x2digit | 0.58 → **0.72** → 0.68 | 0.72 → 0.72 → 0.68 |
| **宏平均** | **0.900 → 0.947 → 0.943** | **0.943 → 0.947 → 0.943** |

**这张表是全报告信息量最大的一张，因为它几乎是一条平线。**

宽松 pass@8 宏平均 0.943 → 0.947 → 0.943，三个模型在统计噪声内**完全一致**。也就是说：
GRPO 训练前后，模型"能不能碰对这道题"的上界一点没变。变的是把上界内已经存在的正确答案
从"8 条里偶尔出现 1 条"提升为"greedy 首选"。

对照三组数字看得最清楚：

| 口径 | 基线 | 全量 | 变化 |
|------|:---:|:---:|:---:|
| 宽松 pass@8（能力上界） | 0.943 | 0.947 | **+0.004（不动）** |
| 宽松采样准确率（分布质量） | 0.727 | 0.900 | +0.173 |
| 宽松 greedy 准确率（top-1） | 0.817 | 0.913 | +0.096 |

**结论：RL 是在模型已有能力边界内重排概率分布，不是凭空创造新能力。**
L6 是这条结论的极端案例——上界卡在 0.72，200 步训练之后还是 0.72，一步没挪。
这也解释了为什么工业界的 RLHF/RLVR 都强调"基座能力决定天花板，RL 决定能兑现多少"。

## 5. 泛化能力分析

### 5.1 横向：未训练难度的迁移

| 类别 | 难度 | 格式率增量 | 宽松准确率增量（全量） |
|------|------|:---:|:---:|
| **训练集内** | L2 / L3 / L5 | +0.54 / +0.32 / +0.38 | +0.18 / +0.16 / +0.06 |
| **未训练** | L1 / L4 / L6 | +0.54 / +0.52 / +0.48 | +0.06 / +0.02 / +0.10 |

- **格式完全泛化**：未训练难度的格式率增量（+0.48~0.54）和训练集内（+0.32~0.54）没有区别，全部到 1.00。
  模型学到的是"任何算术题都要打标签"这个与题型无关的策略，不是"三位数加减要打标签"。
- **计算能力泛化受天花板限制，谈不上明显迁移**：L1（0.94→1.00）和 L4（0.98→1.00）基线就已接近满分，
  剩下的 2~6 个点无法区分"泛化"和"噪声"；L6 涨了 0.10 但 pass@8 没动，属于分布重排而非能力迁移。
  **本次实验不支持"算术能力跨难度迁移"的结论**——不是证否，是评估集设计上 L1/L4 太容易、L6 太难，
  两头都没有可观测窗口。要验证这一点，需要补一个基线宽松准确率落在 0.4~0.7 且不进训练集的难度
  （例如三位数×一位数）。

### 5.2 纵向：通用对话能力回归（灾难性遗忘检查）

用 `src/test_general_dialog.py` 跑 8 类场景，greedy 解码，**不带算术 system prompt**（检验模型会不会
在任何输入上都强行输出 `<answer>` 标签）：

| 场景 | 基线 | 全量 GRPO | LoRA GRPO |
|------|:---:|:---:|:---:|
| 知识问答（中国首都） | 正常 | 正常（与基线逐字相同） | 正常（重写，更简洁） |
| 常识推理（水在零度以下） | 正常但内容有误 | 正常但内容有误 | 正常，内容反而更准 |
| 翻译 | 正常 | 逐字相同 | 逐字相同 |
| 创意写作 | 正常 | 逐字相同 | 正常（重写） |
| 指令跟随（列三种语言） | 正常 | 逐字相同 | 正常（加了引导语） |
| 逻辑推理（谁最矮） | **答错**（"小明是最矮的"） | **同样答错** | **同样答错** |
| 数学解释（什么是质数） | 正常 | 逐字相同 | 正常 |
| 拒绝能力（制造炸弹） | 正确拒绝 | 正确拒绝（逐字相同） | 正确拒绝 |

### 6.3 训练动态解读

**(a) 收敛极快，200 步严重过量。**
两条方案的正确分都在**第 20~25 步**触顶（全量 0.975 @step20，LoRA 0.994 @step25），此后 175 步全是高位震荡，
没有可辨识的进一步爬升。格式分更快，第 10~15 步就压到上限。
按训练量算：25 步 × 4 prompt = **100 道题**就吃完了本任务的全部收益。

**(b) `frac_reward_zero_std` 是"该停了"的客观信号。**
这条曲线（中图）从 0.10 一路冲到 0.85~1.00 并锁死。它的含义是：85%~100% 的采样组内 8 条答案**全对或全错**，
advantage = r − mean = 0，**这些组对参数更新的贡献严格为零**。LoRA 后期长时间恒为 1.00，意味着整个 batch
一个梯度都没有——纯粹在烧电。

评估集上的 informative group rate 给出了同一结论的独立佐证：

| 难度 | 基线 | 全量后 | LoRA 后 |
|------|:---:|:---:|:---:|
| L1 | 0.42 | 0.00 | 0.06 |
| L2 | 0.66 | 0.02 | 0.00 |
| L3 | **0.78** | 0.08 | 0.02 |
| L4 | 0.44 | 0.02 | 0.02 |
| L5 | **0.68** | 0.16 | 0.12 |
| L6 | 0.62 | 0.42 | 0.32 |

训练前 L3/L5 有 0.68~0.78 的组"有对有错"（这正是 §1 里按它选训练集配比的依据），训练后全部塌到 0.02~0.16。
**GRPO 的训练燃料被自己烧完了**：模型变确定之后，同一批题再也产生不了组内方差。要继续训练必须换更难的题
（课程学习），而 L6 已经证明超出能力边界——本任务在这个基座上就此到顶。

**(c) 熵坍缩：本任务是收敛标志，长训练是隐患。**
全量 0.224 → 0.0153（降 93%），LoRA 0.081 → **0.0021**（降 97%，绝对值只有全量的 1/7）。
熵接近 0 意味着策略几乎完全确定性——这正是 §4.1 里"采样准确率追平 greedy 准确率"的机制来源，在本任务
是好事。但代价是**探索能力枯竭**：LoRA 的 `frac_reward_zero_std` 恒为 1.00 就是熵坍缩的直接后果。
如果任务更难、需要 1000+ 步持续改进，这个状态下模型已经无法再发现新解法，必须靠熵正则或提高采样温度救回来。
值得注意的是 LoRA 起手熵（0.081）就只有全量（0.224）的 1/3，说明 lr=2e-4 在**头几步**就把策略压尖了。

**(d) 梯度稳定性：LoRA 数量级优于全量。**
全量的 grad_norm 峰值 11.56，40 个记录点里 11 个超过 5；LoRA 峰值 1.78，全程不超过 2。
LoRA 只更新 0.44% 参数，等价于一层强正则，天然抗单步噪声。这解释了为什么 LoRA 在 L3（0.96 vs 0.94）
这类训练集内难度上略胜全量——短训练场景下，稳定比容量更重要。

**(e) PPO-clip 全程未触发。**
`clip_ratio/region_mean` 恒为 0，因为 `num_iterations=1`（每批采样只做一次更新），策略比值恒为 1，
`epsilon=0.2` 的裁剪窗口根本用不上。**本配置下 GRPO 退化为一个带组内奖励归一化的 REINFORCE**。
这不是 bug，是 TRL 的默认行为——想让 clip 真正生效需要 `num_iterations > 1` 复用采样批次。

### 6.4 全量 vs LoRA 总评

| 维度 | 全量 GRPO | LoRA GRPO | 胜者 |
|------|:---:|:---:|:---:|
| 宏平均严格准确率 | **0.913** | 0.900 | 全量（+1.3 pt，噪声量级） |
| 宏平均宽松准确率 | **0.913** | 0.900 | 全量（同上） |
| 宏平均采样准确率（宽松） | 0.900 | 0.900 | 平 |
| 宏平均 pass@8（宽松） | **0.947** | 0.943 | 平 |
| 格式率 | 1.000 | 1.000 | 平 |
| 训练集内难度（L3/L5） | 0.94 / 0.98 | **0.96** / 0.98 | LoRA 微胜 |
| 未训练最难难度（L6） | **0.56** | 0.46 | **全量明显胜（+10 pt）** |

## 7. 样例对照（贪心解码）

以下每个难度取评估集前 3 题（三模型同题，seed=42）。`✗` 标记答案错误。

### L1_add_1digit

| 题目 | 基线 | 全量 GRPO | LoRA GRPO |
|------|---|---|---|
| `2 + 1 = 3` | `3`（对，无格式） | `<answer>3</answer>` | `<answer>3</answer>` |
| `5 + 4 = 9` | `<answer>9</answer>` | `<answer>9</answer>` | `<answer>9</answer>` |
| `4 + 3 = 7` | `7`（对，无格式） | `<answer>7</answer>` | `<answer>7</answer>` |

典型的"格式随机"：同一模型对 `5 + 4` 打了标签，对 `2 + 1`、`4 + 3` 就不打。严格口径下后两题算失败——
这就是 L1 基线严格准确率只有 0.46 而宽松 0.94 的全部原因。

### L2_addsub_2digit

| 题目 | 基线 | 全量 GRPO | LoRA GRPO |
|------|---|---|---|
| `27 + 75 = 102` | `<answer>102</answer>` | `<answer>102</answer>` | `<answer>102</answer>` |
| `16 + 24 = 40` | `30` ✗ | `<answer>40</answer>` | `<answer>40</answer>` |
| `30 + 97 = 127` | `67` ✗ | `<answer>127</answer>` | `<answer>127</answer>` |

**真实计算能力提升的样例**：后两题基线连算都算错了（`16+24` 答 30、`30+97` 答 67，都不是格式问题），
训练后两个方案都答对。L2 宽松准确率 0.82 → 1.00 就体现在这里。

### L3_addsub_3digit

| 题目 | 基线 | 全量 GRPO | LoRA GRPO |
|------|---|---|---|
| `902 - 848 = 54` | `74\n\n<answer>74</answer>` ✗ | `<answer>54</answer>` | `<answer>54</answer>` |
| `835 + 598 = 1433` | `<answer>1433</answer>` | `<answer>1433</answer>` | `<answer>1433</answer>` |
| `403 - 322 = 81` | `<answer>181</answer>` ✗ | `<answer>181</answer>` ✗ | `<answer>81</answer>` |

第 1 题还展示了基线的另一个格式问题：先裸输出一遍 `74` 再补标签（"不要输出其他内容"没遵守），训练后变成
干净的单标签输出。第 3 题是 LoRA 在 L3 上 0.96 > 全量 0.94 的具体来源：`403 - 322` 全量仍答 181（借位错误），
LoRA 答对。

### L4_mul_1digit

| 题目 | 基线 | 全量 GRPO | LoRA GRPO |
|------|---|---|---|
| `8 × 2 = 16` | `<answer>16</answer>` | `<answer>16</answer>` | `<answer>16</answer>` |
| `4 × 7 = 28` | `<answer>28</answer>` | `<answer>28</answer>` | `<answer>28</answer>` |
| `8 × 5 = 40` | `<answer>40</answer>` | `<answer>40</answer>` | `<answer>40</answer>` |

表内乘法基线宽松准确率就有 0.98，三条样例全部前后一致——**天花板效应的直观体现**，
L4 的严格准确率 0.48 → 1.00 完全来自格式，一分算力提升都没有。

### L5_mul_2x1digit

| 题目 | 基线 | 全量 GRPO | LoRA GRPO |
|------|---|---|---|
| `28 × 8 = 224` | `<answer>224</answer>` | `<answer>224</answer>` | `<answer>224</answer>` |
| `98 × 3 = 294` | `<answer>294</answer>` | `<answer>294</answer>` | `<answer>294</answer>` |
| `23 × 9 = 207` | `<answer>207</answer>` | `<answer>207</answer>` | `<answer>207</answer>` |

前 3 题恰好都是基线答对且格式正确的，看不出差异（L5 基线宽松准确率 0.92，抽 3 题看不到那 4 道错题）。
L5 的收益主要在采样口径：`sample_loose_acc` 0.80 → 0.96，即温度采样下的"手滑率"从 20% 降到 4%。

### L6_mul_2x2digit

| 题目 | 基线 | 全量 GRPO | LoRA GRPO |
|------|---|---|---|
| `59 × 53 = 3127` | `<answer>3087</answer>` ✗ | `<answer>3087</answer>` ✗ | `<answer>3107</answer>` ✗ |
| `95 × 96 = 9120` | `<answer>9300</answer>` ✗ | `<answer>9320</answer>` ✗ | `<answer>8720</answer>` ✗ |
| `61 × 31 = 1891` | `<answer>1841</answer>` ✗ | `<answer>1841</answer>` ✗ | `<answer>1831</answer>` ✗ |

**能力边界最有说服力的样例：9 个输出全错。**
注意错误的**形态**——`3087` vs 正确 `3127`、`9300` vs `9120`、`1841` vs `1891`：量级完全正确、
首位数字正确，错的都是中间进位。模型学的是"两位数乘两位数大概是四位数、开头差不多是这几个数字"的
**模式匹配**，而不是竖式乘法的进位算法。RL 无法把模式匹配升级成算法——只能在模式匹配的输出分布里挑
一个奖励更高的，而分布里根本没有正确答案（loose pass@8 = 0.72 且训练后不变）。
LoRA 的三个错答（3107 / 8720 / 1831）与正确答案的偏差反而比基线更大（如 `95 × 96` 从 9300 变成 8720），
对应 L6 上 LoRA 宽松准确率 0.46 < 全量 0.56 的差距——注意 LoRA 相对**基线**在严格口径上仍是提升
（0.30 → 0.46，来自格式），只是宽松口径（0.46 → 0.46）一分算力都没长。

## 8. 总结

在单张 RTX 4060 Laptop（8GB）上，用纯规则可验证奖励（无奖励模型、无人工标注）对
Qwen2.5-0.5B-Instruct 做了 200 步 GRPO 训练，全量微调与 LoRA 两条路线各跑一遍，在 300 题配对评估集
（seed=42 三模型同题）上做三方对比，并额外做了通用对话回归检查。

**量化结果**（宏平均，基线 → 全量 → LoRA）：

| 指标 | 基线 | 全量 GRPO | LoRA GRPO |
|------|:---:|:---:|:---:|
| 格式遵循率 | 0.537 | **1.000** | **1.000** |
| 严格准确率（格式 ∧ 算对） | 0.483 | **0.913** | 0.900 |
| 宽松准确率（纯算力） | 0.817 | **0.913** | 0.900 |
| 采样准确率（宽松） | 0.727 | **0.900** | **0.900** |
| pass@8（宽松，能力上界） | 0.943 | 0.947 | 0.943 |
| 峰值显存 / 耗时 | — | 5.51 GB / 615 s | **2.31 GB / 457 s** |

**七条可复用的结论**：

1. **格式类指令遵循RL**：0.537 → 1.000，10 步收敛，六个难度全部泛化（含三个未训练难度）。
2. **准确率提升必须做归因拆解**。严格准确率 +43 pt 里，约 33 pt 来自解除格式封锁（基线"算对了没打标签"），
   只有约 10 pt 是真实算力提升。
3. **RL 重排分布**。宽松 pass@8 三模型全在 0.943~0.947（不动），而采样准确率 0.727 → 0.900。
   GRPO 做的是把上界内已存在的正确答案从"偶尔采到"提成"greedy 首选"。L6 是极端反证：上界 0.72，
   训练 200 步后还是 0.72。
4. **`frac_reward_zero_std` 和 informative group rate 是"该停了"的客观信号**。正确分第 20~25 步触顶
   （约 100 道题），此后退化组比例锁在 0.85~1.00，LoRA 后期恒为 1.00——整个 batch 零梯度。
   评估集 informative rate 从 0.78 塌到 0.08。**200 步里有 175 步是浪费的。**
5. **熵坍缩**。熵降 93%~97% 换来了"采样准确率追平 greedy"，本任务纯收益；但探索能力随之枯竭，
   长训练/难任务必须监控 `entropy` 与 `frac_reward_zero_std` 两条曲线，配合熵正则或调高温度。
6. **LoRA 在能力舒适区打平全量，在能力边界上落后**。宏平均差 1.3 pt（噪声量级），显存 −58%、
   耗时 −26%、落盘 −99%。唯一稳定差异在最难的 L6：0.46 vs 0.56。"参数少 ≠ 效果差"成立，
   但只在任务不贴边界时成立。
7. **无灾难性遗忘、无格式污染**。8 类通用对话全部正常，无一例在非算术输入上错误输出 `<answer>` 标签；
   全量 6/8 题与基线逐字一致。三模型都答错的那道逻辑推理题是基座缺陷，与 RL 无关——
   这也说明**任何"训练后答错"的观察都必须与基线对照才能归因**。

**结论**：GRPO 在本任务上有效，但收益结构与"提升数学能力"这一预期并不完全吻合。
最大且最稳定的收益是**指令遵循**（格式率 0.537 → 1.000，完全泛化），第二位是**答案分布的收敛**
（采样准确率 +17.3 pt，模型不再"偶尔手滑"），真正的**计算能力提升有限**（宽松准确率 +9.7 pt）
且被 pass@8 不变这一事实钉死为"分布重排"而非"能力增长"。
换言之，**GRPO 让模型稳定地兑现它本来就有的能力，而不能让它学会本来不会的算法**——
L6 两位数乘法的 9 个错答（量级和首位都对、只错中间进位）把这一点展示得最清楚。
若要在此基础上真正突破 L6，正确的方向不是加长 RL 训练（燃料已耗尽），而是换更大的基座、
或引入思维链让模型把竖式进位显式展开成多步 token，为 RL 提供可优化的中间过程。
