## 二、混元 Hy3 详解

### 2.1 总体特点

- **定位**：快慢思考融合的 MoE 模型，总参数 295B、激活 21B、上下文 256K。
- **核心理念**：官方自述"实用主义"——不追求单项榜单第一，追求综合能力 + 真实场景可用 + 成本效率。
- **架构上最大的特点**：**几乎没有架构创新，完全走"标准件 + 高稀疏度 + 软硬协同"路线**。这与 DeepSeek/Kimi/Qwen 纷纷上 MLA/线性注意力/稀疏注意力的潮流形成鲜明对比。

### 2.2 模型结构（从 `hy3_model.py` + `tencent_Hy3_config.json` 读出）

| 模块 | 结构 | 关键参数 |
|---|---|---|
| **注意力** | 标准 **GQA + QK-Norm** | 64 头 / 8 KV 头，head_dim=128 |
| 位置编码 | **RoPE**（默认类型） | rope_theta=11,158,840 |
| FFN | **SwiGLU**（gate/up/down） | intermediate_size=13312 |
| **MoE** | 标准 top-k 路由 | **192 专家 / 8 激活 / 1 共享**，expert 中间维 1536 |
| 路由函数 | **sigmoid**（非 softmax） | router_scaling_factor=2.826，含 `e_score_correction_bias` |
| 稀疏比 | 激活 21B / 总 295B ≈ **1/14** | 前 1 层 dense（`first_k_dense_replace=1`） |
| 预测加速 | **MTP**（多 token 预测） | `num_nextn_predict_layers=1` |
| 归一化 | RMSNorm + Pre-Norm | rms_norm_eps=1e-5 |
| 层数/隐藏维 | 80 层，hidden=4096 | vocab=120832 |

### 2.3 代码层面的细节

```python
class HYV3Attention(nn.Module):
    """Multi-headed attention from 'Attention Is All You Need' paper"""
    # 标准 q/k/v/o 投影 + q_norm/k_norm（QK-Norm）
    self.q_norm = HYV3RMSNorm(self.head_dim, ...)
    self.k_norm = HYV3RMSNorm(self.head_dim, ...)
```

- 路由用 sigmoid 打分 + `topk` 选专家，并对权重做 **`router_scaling_factor` 额外缩放**（`top_k_weights * 2.826`），这是它区别于标准 MoE 的一个微调点。
- `e_score_correction_bias` 作为专家分数的可学习偏置（类似 DeepSeek 的 bias term），用于负载均衡与专家偏好矫正。
- MTP 层在第 81 层（`_keys_to_ignore_on_load_unexpected = [r"model\.layers\.80.*"]`），当前 transformers 尚未支持其推理。

**一句话总结**：Hy3 = **标准 GQA + QK-Norm + SwiGLU + sigmoid 路由 MoE(192→8) + MTP**，靠"高稀疏度 + 快慢思考 + 工程优化"而非架构创新取胜。

## 三、MiniMax M3 详解

### 3.1 总体特点

- **定位**：原生多模态模型，总参数 ~428B、激活 ~23B、上下文 **1M**，支持文本/图像/视频。
- **核心理念**：用 **MSA（MiniMax Sparse Attention，块稀疏注意力）** 解决超长上下文的二次复杂度问题——1M 上下文下相比 M2 实现 **9× prefill / 15× decode 加速，每 token 计算量降到 1/20**。

### 3.2 模型结构（从 `minimax_m3_model.py` + `MiniMaxAI_MiniMax-M3_config.json` 读出）

| 模块 | 结构 | 关键参数 |
|---|---|---|
| **注意力** | **GQA + Gemma 风格 QK-Norm + partial RoPE + MSA 块稀疏注意力** | 64 头 / 4 KV 头，head_dim=128 |
| 稀疏注意力 | **"Lightning Indexer"** 块稀疏选择 | index 4 头，block=128，每 query 选 top-16 blocks + 1 个 local block |
| FFN | **SwiGLU-OAI**（带 alpha/limit） | swiglu_alpha=1.702，swiglu_limit=7.0 |
| **MoE** | top-k 路由 | **128 专家 / 4 激活 / 1 共享**，dense 中间维 12288 |
| 路由函数 | **sigmoid** | routed_scaling_factor=2.0 |
| 稀疏比 | 激活 23B / 总 428B ≈ **1/19**（激活专家最少，仅 4） | 前 3 层 dense |
| 预测加速 | **MTP**（**7 个 MTP 模块**，最激进） | `num_mtp_modules=7` |
| 视觉分支 | ViT 32 层 + patch merge | patch=14，输入 2016²，投影到 6144 |
| 层数/隐藏维 | 60 层，hidden=6144 | vocab=200064 |

### 3.3 MSA 稀疏注意力的核心（`MiniMaxM3VLIndexer`）

```python
class MiniMaxM3VLIndexer(nn.Module):
    """Lightning Indexer ... Scores each query against every key with a small
    index_n_heads-head ... keeps, per query, the top-index_topk_blocks key blocks
    plus the index_local_blocks blocks immediately preceding ..."""
```

- 用一个**轻量 indexer**（4 头、128 维）对每个 query 与所有 key 打分；
- 以 **128 token 为 block**，每个 query 只保留打分最高的 **16 个 block** + 前 1 个 local block；
- 结果做 **块级稀疏**（block-sparse）注意力，长序列时计算量大幅下降；
- 源码注释明确写着 **"Like DeepSeek-V4's indexer this is purely a *selection* branch"**——与 DeepSeek-V4 的稀疏选择分支同源设计。

**一句话总结**：M3 = **GQA + Gemma QK-Norm + MSA 块稀疏注意力 + SwiGLU-OAI + sigmoid 路由 MoE(128→4) + 7×MTP + 原生多模态**，是"稀疏注意力攻坚超长上下文"路线的代表。

## 四、对比模型速览（DeepSeek / Kimi / Qwen / GLM）

### 4.1 DeepSeek V3（`deepseek-ai_DeepSeek-V3_config.json`）

- **注意力**：**MLA**（Multi-head Latent Attention，KV 低秩压缩：`kv_lora_rank=512`，q_lora_rank=1536，qk_nope/qk_rope 解耦）。
- **MoE**：256 专家 / 8 激活 / 1 共享，sigmoid + `noaux_tc` 无辅助损失路由，前 3 层 dense。
- **加速**：MTP 1 层；fp8 量化。
- **上下文**：128K（YaRN 扩展）。
- **定位**：671B / 激活 37B，MLA + MoE 的行业标杆。

### 4.2 DeepSeek V4（Flash 变体，`deepseek-ai_DeepSeek-V4-Flash_config.json`）

- **注意力**：`Attention` 类注释原文 **"Multi-head Latent Attention (MLA) with sliding window + optional KV compression"**——在 MLA 基础上叠加：
  - **sliding window（128）**；
  - **Compressor（KV 压缩，`compress_ratios`）**；
  - **Indexer（稀疏 top-k 选择，含 hash 索引 + Sinkhorn，`index_topk=512`，`num_hash_layers=3`）**。
- 超大头维 `head_dim=512`，43 层，hidden=4096。
- **MoE**：256 专家 / 6 激活 / 1 共享，专家 fp4 量化。
- **上下文**：1M；MTP 1 层。

### 4.3 Kimi K3（`moonshotai_Kimi-K3_config.json`）

- **注意力**：**混合线性注意力**——以 **KDA（Kimi Delta Attention，线性注意力）** 为主，每 4 层穿插一个 full attention（`full_attn_layers` 每隔 4 层）；同时保留 **MLA**（`mla_use_nope`、`mlp_use_output_gate`）。
- **MoE**：**896 专家 / 16 激活 / 2 共享**（专家数全表最多），latent MoE，`moe_renormalize`。
- **激活**：`situ` 激活函数（自研）。
- **无 MTP**（`num_nextn_predict_layers=0`）。
- 93 层，hidden=7168，多模态（ViT 27 层），上下文 1M。

### 4.4 Qwen3.6（`Qwen_Qwen3.6-*_config.json`）

- **注意力**：**Gated DeltaNet 线性注意力**（`linear_attn` / `GatedDelta`）+ 门控输出（`attn_output_gate`），**每 4 层一个 full attention**（`full_attention_interval=4`）。
- **两个版本**：
  - **27B**：dense（64 层，hidden=5120，head_dim=256）。
  - **35B-A3B**：MoE（40 层，hidden=2048，256 专家 / 8 激活 / 1 共享）。
- **加速**：MTP 1 层。
- 多模态（ViT 27 层，patch 16），上下文 256K。

### 4.5 GLM-5.2（`zai-org_GLM-5.2_config.json`）

- **注意力**：**MLA + DSA（Dynamic Sparse Attention，动态稀疏注意力）**——`GlmMoeDsaIndexer` 做稀疏选择（`index_topk=2048`，index 32 头，每 4 层做一次 index，`index_topk_freq=4`）。
- **MoE**：256 专家 / 8 激活 / 1 共享，sigmoid，前 3 层 dense。
- **加速**：MTP 1 层。
- 78 层，hidden=6144，上下文 1M，rope_theta=8,000,000。

## 六、相似点分析

### 6.1 都是"MoE 稀疏激活"路线

6 个模型中除 Qwen3.6-27B（dense）外，全部采用 **MoE（混合专家）**。共同点是：
- 都采用 **"稀疏专家 + 共享专家"** 结构（`num_shared_experts=1` 几乎通用，Kimi 为 2）；
- 前几层用 dense FFN 过渡（`first_k_dense_replace`：Hy3=1、DeepSeek=3、GLM=3、M3=3、Kimi=1）；
- 路由函数**全部用 sigmoid**（而非传统 softmax），这是 2024 年 DeepSeek-V3 带起的标准做法，Hy3、M3 都继承了。

### 6.2 都在用 QK-Norm / RMSNorm 这类稳定训练技巧

- Hy3、MiniMax-M3、GLM、DeepSeek、Kimi、Qwen **全部使用 RMSNorm**；
- Hy3 的 QK-Norm、M3 的 Gemma 风格 per-head QK-Norm，是新一代模型共同采用的注意力稳定性技巧（源自 DeepSeek-V2 与 Gemma 系列）。

### 6.3 都用 MTP（多 token 预测）加速推理

除 Kimi K3 外，**Hy3、M3、DeepSeek V3/V4、Qwen、GLM 都带 MTP 层**——说明 MTP 已成为 2025–2026 开源大模型的"标配"加速手段。

### 6.4 都在用 RoPE 位置编码

所有模型统一采用 **RoPE**（仅 theta 值与变体不同：Hy3=11.16M、M3=5M、GLM=8M、Qwen=10M），并普遍使用 partial/interleave 等 RoPE 变体。

## 七、不同点分析

### 7.1 注意力机制是最大的分水岭（四条技术路线）

| 路线 | 代表模型 | 核心思想 |
|---|---|---|
| **朴素 dense GQA** | **Hy3** | 不搞注意力创新，靠 MoE 稀疏 + 工程降本 |
| **稀疏注意力**（块稀疏索引选择） | **MiniMax-M3(MSA)、DeepSeek-V4(Indexer)、GLM(DSA)** | 用轻量 indexer 选出 top-k 块，只算重要块的注意力 |
| **线性注意力**（RNN/SSM 式） | **Kimi K3(KDA)、Qwen3.6(Gated DeltaNet)** | 用固定大小状态替代 KV cache，长序列 O(n) |
| **MLA**（KV 低秩压缩） | **DeepSeek、Kimi、GLM** | 把 KV 压缩到低秩空间，减小 KV cache |

> **关键洞察**：Hy3 是这批模型里**唯一坚持纯 dense 全注意力**的，而其他模型都至少上了一种"注意力降本"技术。Hy3 的选择印证了其"务实"定位——用 192→8 的高稀疏度（激活仅 21B）+ 硬件协同优化，同样达到了旗舰级性价比，把注意力创新的复杂度留给了别人。

### 7.2 超长上下文（1M）的实现手段各不相同

| 模型 | 实现 1M 上下文的手段 |
|---|---|
| MiniMax-M3 | **MSA 块稀疏注意力** |
| DeepSeek-V4 | **滑窗 + KV 压缩 + 稀疏 Indexer** |
| Kimi K3 | **线性注意力 KDA** |
| GLM-5.2 | **动态稀疏注意力 DSA** |
| Hy3 / Qwen | 只到 256K（不追求 1M） |

### 7.3 MoE 的"稀疏度"取舍不同

- **激活专家数**：MiniMax-M3 最激进（**只激活 4 个**，128 专家，稀疏比约 1/19）；Kimi 最"密"（激活 **16 个**，896 专家）；其余多为 8 个。
- **专家总数**：Kimi 的 **896 专家**断层领先，是 Hy3(192) 的近 5 倍——Kimi 用"海量小专家 + 高激活数"探索另一条路。
- Hy3 的 **192 专家 / 8 激活** 是相对保守的中间配置。

### 7.4 多模态能力差异

- **原生多模态**：MiniMax-M3（文本+图像+视频，混合模态从第一步就训练）、Kimi K3、Qwen3.6（都带 ViT 视觉分支）。
- **纯文本**：Hy3、DeepSeek V3/V4、GLM-5.2（这三个是纯语言模型）。

### 7.5 MTP 的激进程度

- **MiniMax-M3 独一档**：**7 个 MTP 模块**（`num_mtp_modules=7`），远超其他模型的 1 个；
- Kimi K3 反而**不用 MTP**（=0），依赖其线性注意力的高效生成。

## 八、关键洞察与结论

1. **Hy3 是"反内卷"的务实派**：在 DeepSeek/Kimi/Qwen/GLM 纷纷押注 MLA、稀疏注意力、线性注意力时，Hy3 回到最朴素的标准 GQA + QK-Norm + SwiGLU + MoE，用 **295B→21B 的高稀疏度 + 快慢思考融合 + 软硬协同优化**达成旗舰级性价比。它证明了"架构简单 + 工程到位"同样能打。

2. **MiniMax-M3 是"稀疏注意力"路线的集大成者**：MSA（Lightning Indexer 块稀疏）+ 7×MTP + 原生多模态，把 1M 上下文做到了 9×/15× 加速，且源码明确与 DeepSeek-V4 的 indexer 同源——说明**"块稀疏索引选择"正在成为超长上下文的主流方案**（M3、DeepSeek-V4、GLM-DSA 三家殊途同归）。

3. **四条注意力路线已成型**，可概括为：**朴素 GQA（Hy3）｜块稀疏选择（M3/V4/GLM）｜线性注意力（Kimi/Qwen）｜MLA 低秩（DeepSeek/Kimi/GLM）**，且后三者经常叠加使用（如 Kimi = 线性 + MLA，GLM = MLA + DSA）。

4. **共性收敛**：sigmoid 路由 MoE、RMSNorm、RoPE、MTP、共享专家、前几层 dense——这些已成为 2025–2026 开源大模型的"通用底座"，各家真正的差异集中在**注意力降本方案**和**稀疏度配置**两个维度上。
