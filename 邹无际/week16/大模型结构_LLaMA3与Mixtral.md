# 开源大模型结构调研：LLaMA 3 与 Mixtral 8x7B

这次我调研了两个开源大模型的结构：**Meta 的 LLaMA 3** 和 **Mistral AI 的 Mixtral 8x7B**。选它们是因为这两个模型正好代表了开源大模型的两种主流思路：LLaMA 3 是"密集"结构，所有参数每个 token 都参与计算；Mixtral 把前馈网络换成了"专家混合"（MoE），一个 token 只激活其中两个专家。一个靠堆规模，一个靠省算力，放在一起看，能很清楚地看出 2023 年以来开源模型的结构走向。

## LLaMA 3（Meta）

LLaMA 3 是 Meta 在 2024 年 4 月开源的，首批给了 8B 和 70B 两个尺寸，7 月又补了 405B 的旗舰版。说它是当时开源社区的事实基线不算夸张，后来一大堆微调、蒸馏模型都是拿它当底子的。

结构上是标准的 decoder-only Transformer：输入 token 先过 embedding 层，然后串 32 层（8B）或 80 层（70B）完全相同的解码层，最后接输出层预测下一个 token。每一层内部就两个子层——多头自注意力加前馈网络，都是先归一化再进子层（Pre-Norm），再套残差连接：

```
输入序列 ──► Token Embedding ──► ┌────────────────────────────────┐
                                 │  解码层 × L（8B 是 32 层）        │
                                 │  ┌────────────────────────────┐  │
                                 │  │ RMSNorm ─► GQA 注意力       │  │
                                 │  │        （+ RoPE）           │  │
                                 │  │        （+ 残差）            │  │
                                 │  ├────────────────────────────┤  │
                                 │  │ RMSNorm ─► SwiGLU FFN      │  │
                                 │  │        （+ 残差）            │  │
                                 │  └────────────────────────────┘  │
                                 └────────────────────────────────┘
                                        │
                                  输出层（预测下一个 token）
```

里面几个组件值得逐个说一下。

**归一化用的是 RMSNorm。** LLaMA 从第一代起就不用标准 LayerNorm。区别在于 LayerNorm 要先算均值和方差、把数据"中心化"，RMSNorm 只保留缩放那一步：

$$
\text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\sum_{i=1}^{d} x_i^2 + \epsilon}} \cdot \gamma
$$

少算了均值，省一点计算量，效果在深层网络里也差不多，所以大家就都跟上了。$\epsilon$ 是防止除零的小常数，LLaMA 3 取 $1\times10^{-5}$。

**位置编码用的是 RoPE（旋转位置编码）。** 这是苏剑林他们 2021 年提的，思路是把位置信息变成对 Q、K 向量的旋转操作，旋转过的 Q、K 做内积时自然带上相对位置信息。它最好的地方是外推能力：训练时没见过那么长的序列，换长一点的也能凑合着用。LLaMA 3 把 RoPE 的基频 theta 从 LLaMA 2 的 10,000 提到了 **500,000**，低频分量转得慢了，对长距离位置的敏感度上来了，长文本能力因此强了不少，也为后面 LLaMA 3.1 把上下文从 8K 扩到 128K 铺了路。

**前馈网络用的是 SwiGLU 激活：**

$$
\text{SwiGLU}(x) = \big(\text{Swish}(x W_g) \odot (x W_u)\big)\, W_d
$$

和普通 ReLU FFN 比多了一个门控矩阵（三个权重矩阵而不是两个），表达能力强一些，代价是参数变多。现在开源模型几乎清一色用它。

**注意力这块用了 GQA（分组查询注意力）。** 标准多头注意力（MHA）每个头都配一套自己的 K/V 投影，推理时要缓存所有头的 K/V，序列一长显存和带宽都扛不住。GQA 的办法是让几个 Q 头共用一组 K/V 头，是 MHA 和"多查询注意力"（所有头共一组）之间的折中：8B 是 **32 个 Q 头、8 个 KV 头**，等于每 4 个 Q 头分一组共享一套 K/V；70B 是 64 个 Q 头、8 个 KV 头。质量损失很小，KV 缓存却小了一大截，推理快很多。LLaMA 2 只有 70B 用了 GQA，7B/13B 还是 MHA，LLaMA 3 是全系列统一，这一步明显是为了部署效率，说明 Meta 从一开始就把推理成本算进去了。

**Tokenizer 也换得挺大。** LLaMA 2 用 SentencePiece，词表 32,000；LLaMA 3 换成 OpenAI 的 tiktoken，词表一口气扩到 **128,256**。好处有两个：一是分词压缩率高，同样一段话 token 数更少，训练和推理都省钱；二是多语言支持明显变好，覆盖了 30 多种语言。

具体配置如下（8B 和 70B 两个尺寸）：

| 配置项 | LLaMA 3 8B | LLaMA 3 70B |
|---|---|---|
| 层数 | 32 | 80 |
| 隐层维度 | 4,096 | 8,192 |
| Q 头数 | 32 | 64 |
| KV 头数（GQA） | 8 | 8 |
| FFN 中间维度（SwiGLU） | 14,336 | 28,672 |
| 词表大小 | 128,256 | 128,256 |
| 训练上下文长度 | 8,192 | 8,192 |
| RoPE base | 500,000 | 500,000 |
| 归一化 | RMSNorm（Pre-Norm） | RMSNorm（Pre-Norm） |
| bias | 无 | 无 |

除了结构上的这些改动，LLaMA 3 还有一点我觉得比结构本身更值得注意：**预训练数据堆到了 15T+ tokens**（LLaMA 2 大概是 2T），而且强调质量优先于数量，用启发式规则加一个基于 Llama 2 的分类器做清洗去重，过滤之后高质量数据占比提到一半以上。同架构下数据翻几倍，能力差距就是质变。训练管线是预训练之后走 SFT + RLHF，instruct 版用拒绝采样做偏好优化，8B 在同量级模型里表现相当能打。后来的 405B 旗舰是 126 层、隐层 16,384、上下文 128K，还开源了用 405B 蒸馏出来的 8B/70B 小模型，等于直接搭了一整套大小模型的生态。

## Mixtral 8x7B（Mistral AI）

Mixtral 8x7B 是法国公司 Mistral AI 在 2023 年 12 月发的，Apache 2.0 协议，权重和代码全开放。它是当时开源界最能打的稀疏 MoE 模型，数学、代码、多语言评测都排在最前面，也第一次让很多人（包括我）意识到：原来"模型很大"和"推理很贵"可以不绑定。

它的整体结构还是 decoder-only Transformer，和 Mistral 7B 的区别只有一处：**每一层的前馈网络被换成了稀疏 MoE 层**。这个 MoE 层由两部分组成：**8 个专家**（每个专家就是一个独立的 SwiGLU 前馈网络，中间维度 14,336），以及一个**路由网络（Router）**，给每个 token 打 8 个分数，挑出分数最高的 2 个专家来算。所以每个 token 实际只过 2 个专家，另外 6 个是闲着的：

```
输入 token x
      │
      ▼
┌─────────────┐   top-2 选择
│   Router    │───────────────►  Expert 3（权重 w₃）
│ (线性+softmax)│                 Expert 7（权重 w₇）
└─────────────┘
      │
      ▼
输出 = w₃ · FFN₃(x) + w₇ · FFN₇(x)   （其余专家跳过）
```

MoE 层的输出是被选中专家输出的加权和，权重就是 Router 的 softmax 分数，整个过程对输入可微，梯度能正常往回传，训练和普通 Transformer 没什么两样。

MoE 的想法其实不新，2017 年 Shazeer 他们就在稀疏门控的 MoE 上做过实验，但真正做成能用的开源产品，Mixtral 算是标志性的一个。它的参数账是这么算的：**总参数 46.7B**——8 个专家加上注意力这些，模型"记的东西"很多；但**每个 token 只激活约 12.9B 参数**——注意力全量算，FFN 只走 2 个专家。结果就是推理计算量跟 13B 左右的密集模型差不多，容量却接近大得多的模型。用大白话说，等于"请了 8 个专家，但每次只付 2 个人的工资"。Router 就是一个线性层，对 token 隐状态 $h$ 算 $g_i = \text{softmax}(h \cdot W_{router})_i$，取前 2 个做加权和：

$$
y = \sum_{i \in \text{top-2}} g_i \cdot \text{FFN}_i(x)
$$

固定选 top-2（而不是设阈值）有个实际好处：每个 token 的计算量恒定，批处理和推理都好规划。训练时 Router 会加一点噪声扰动，防止某几个专家总被选中、其他的闲死——MoE 训练里"专家负载不均"是老大难问题。

其它组件基本沿用 Mistral 7B：GQA（32 Q 头、8 KV 头）、RMSNorm + Pre-Norm、RoPE、SwiGLU，一模一样。有个区别是 Mixtral **去掉了滑窗注意力**，直接全注意力上 32K 上下文——Mistral 7B 要靠滑窗来省长序列开销，Mixtral 因为 MoE 省下来的算力，可以任性一点。Tokenizer 是词表 32,000 的 BPE，原生支持英语、法语、意大利语、德语、西班牙语几种欧洲语言，中文不在原生范围内，实际使用得靠扩充词表或加中文数据微调。

| 配置项 | Mixtral 8x7B |
|---|---|
| 架构类型 | Decoder-only + 稀疏 MoE |
| 层数 | 32 |
| 隐层维度 | 4,096 |
| Q 头数 | 32 |
| KV 头数（GQA） | 8 |
| 专家数量 | 8 |
| 每 token 激活专家数 | 2（top-2） |
| 专家 FFN 中间维度 | 14,336 |
| 总参数量 | **46.7B** |
| 每 token 激活参数量 | **约 12.9B** |
| 词表大小 | 32,000 |
| 上下文长度 | 32,768 |
| 归一化 / 激活 | RMSNorm / SwiGLU |
| 许可证 | Apache 2.0 |

后来 Mistral 又发了 Mixtral 8x22B（总参数约 141B、激活约 39B），说明"8 专家 + top-2"这套结构放大几倍照样能 work，不是只能在小模型上玩玩。

看完这两个模型，我最大的感受是：它们的分歧其实就一句话——LLaMA 3 赌的是"结构不变，把规模和数据堆上去"，Mixtral 赌的是"换个组织方式，用同样的算力装下更大的模型"。有意思的是两边用的组件（RMSNorm、RoPE、SwiGLU、GQA）几乎完全一样，差的只是前馈网络的组织形式。这大概说明 Transformer 的"积木"已经收敛了，真正的创新正在从"发明新模块"转移到"怎么更高效地把现有模块组织起来"。资料方面主要参考了 Meta 和 Mistral 的官方博客、技术报告以及 HuggingFace 上的模型配置，交作业前最好联网核对一遍文中的数字。
